## Architectural Understanding

### Theme Inheritance System
- **Location**: `main/app/Services/ThemeManager.php`
- **Function**: `ThemeManager::getThemeInheritanceChain($themeName)`
- **Behavior**: Returns ordered array: child theme → parent theme → grandparent → ... → default (final fallback)
- **Themes**:
  - **Built-in**: default (base), light, dark, blue, premium, materialize
  - **Custom**: trading-v1 (has own layout)
- **Order for theme assets**:
    - trading-v1: trading-v1 → default (for missing assets)
    - light: light → default
    - dark: dark → default
    - blue: blue → default
    - premium: premium → default
    - materialize: materialize → default

### Asset Loading Functions
- **Config::cssLib($folder, $filename)** in `main/app/Helpers/Helper.php`:
  - First checks current theme's asset path
  - Falls back to parent themes via inheritance chain
  - Returns appropriate asset path
- **Config::jsLib($folder, $filename)**: Similar behavior for JavaScript assets

**Impact**: Any theme can override assets by having files; others inherit from parents or default

### Route Structure
- **Standard Routes**: `user.dashboard`, `user.ticket.*`, `user.wallet.*`, `user.deposit.log`, etc.
- **Beta Routes**: `beta.dashboard`, `beta.terminal.*`, `beta.trading.*`, `beta.ticket.*`
- **Trading Routes**: `user.trading.*` (unified trading management)
  - Configuration: `user.trading.configuration.*` (routes exist but named as user.trading.configuration.*)
  - Execution Log: `user.trading.execution-log.*`
  - Marketplaces: `user.trading.marketplaces.*`
  - Backtesting: `user.trading.backtesting.*`
  - Multi-Channel Signal: `user.trading.multi-channel-signal.*`

**Sidebar Route Pattern Strategy**:
- trading-v1 uses `beta.*` patterns for ALL its routes
- Other themes use `user.*` patterns for standard routes
- Both coexist because they target different route groups
